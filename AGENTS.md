# Инструкции для работы над Wordle в Telegram

Проект — Telegram-бот с русской Wordle в HTML-виджете внутри сообщения. Первая версия предназначена для личного использования; целевые клиенты — Windows и Android.

## Документы проекта

Перед работой прочитай документы, относящиеся к задаче:

- [docs/design.md](docs/design.md) — согласованные требования и правила игры.
- [docs/implementation-plan.md](docs/implementation-plan.md) — архитектура, этапы, зависимости и критерии готовности.
- [GLOSSARY.md](GLOSSARY.md) — принятые термины.
- `docs/validation.md`, если создан, — фактические результаты проверок.

Правила игры храни в описании, последовательность работ — в плане, определения — в словаре. Не дублируй эти документы здесь. Согласованные решения не требуют повторного интервью; существенные противоречия уточняй у пользователя.

## Порядок работы

- Выполняй текущий запрос пользователя. Запрос на документацию или план не означает разрешение начинать реализацию, устанавливать зависимости или запускать бота.
- При запросе на разработку следуй зависимостям этапов плана. Отмечай задачи выполненными только после достижения их критериев готовности.
- Изменение согласованных требований отражай в описании и соответствующих пунктах плана. Технические уточнения вноси в план с кратким объяснением.
- Не создавай заготовки будущих файлов только потому, что они перечислены в плане.

## Технологии и границы

- Python 3.13 и aiogram 3.x. Используй `Bot`, `Dispatcher`, `Router` и штатный long polling. Точные версии зависимостей закрепляй в `requirements.txt` при реализации.
- Для `sendWidget` сначала проверь поддержку в выбранной версии aiogram. Если готового метода нет, добавь небольшое расширение `TelegramMethod` через штатную сессию библиотеки, как описано в плане.
- Игровая модель, интерфейс и список ответов находятся в автономном HTML с встроенными CSS и JavaScript. Собственный HTTP-клиент и цикл получения обновлений для бота не нужны.
- Состояние партии хранится в `sessionStorage` виджета до перезапуска клиента. Не добавляй долговременное или серверное хранение без изменения согласованных требований.
- Проверяй размер готового HTML по ограничениям плана. При несовместимости не заменяй виджет на Mini App без согласования.

## Проверка работы

Используй Python из проектного `.venv`. После появления реализации основные команды из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests/python -v
node --test
.\.venv\Scripts\python.exe -m wordle_bot.widget --check
```

- Для изменений игровой логики проверяй поведение, включая повторяющиеся буквы, расходование попыток и завершение партии. Используй те же исходники, которые включаются в виджет.
- Перед завершением разработки выполняй весь автоматический набор. Документационные изменения проверяй на согласованность и работоспособность локальных ссылок.
- Проверку в настоящем Telegram выполняй на Windows и Android по матрице плана. Браузерный просмотр и модульные тесты не заменяют эту приёмку.
- Фактические результаты и ограничения записывай в `docs/validation.md`, создавая его при первых проверках реализации.
- Если модулей, токена или устройства пока нет, явно указывай непроверенные пункты. Не заявляй об успешном запуске или прохождении тестов без подтверждения.

## Конфигурация

- `BOT_TOKEN` задаётся пользователем локально. Не записывай настоящий токен в документы, код, тесты или журнал.
- Используй фиктивный токен и локальный сервер для автоматических проверок отправки через aiogram. Действующий Telegram подключай только для интеграционной проверки в рамках запроса на разработку.
